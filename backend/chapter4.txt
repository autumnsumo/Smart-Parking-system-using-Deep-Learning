# CHAPTER 4 - RESEARCH METHODOLOGY

## 4.1 Dataset description
The efficacy of the VGG16 occupancy model and the Hybrid OCR engine relies entirely on the quality, diversity, and volume of the training data. For this research, a multi-source data aggregation strategy was employed.
The primary corpus for the occupancy model was the PKLot dataset. Containing nearly 700,000 images, PKLot is captured from high-vantage points across two different parking lots under drastically different weather conditions: sunny (high glare, sharp shadows), overcast (low contrast, flat lighting), and rainy (reflective asphalt, water droplets). This diversity is critical for training a CNN to ignore environmental noise.
To ensure the model did not overfit to top-down perspectives, the CNRPark and CNRPark-EXT datasets were integrated. These sets feature massive camera perspective distortions, partial occlusions by trees and infrastructure, and low-light scenarios.
Finally, a custom SOCIETY_PARKING dataset was manually curated. Thousands of frames were captured directly from the deployment site's CCTV cameras. Using polygonal annotation tools, precise Regions of Interest (ROIs) were extracted and manually labeled as 0 (Vacant) or 1 (Occupied). This local fine-tuning ensures the model understands the specific asphalt texture, painted line colors, and camera lens distortions unique to the deployment facility.

## 4.2 Data preprocessing
Before any image matrix can be passed into the VGG16 tensors, it must undergo rigorous mathematical preprocessing. Parking slots are typically defined by four-point polygons reflecting the physical space on the ground. Because cameras view these spaces at acute angles, the polygons are highly skewed.
The preprocessing pipeline first calculates the minimum bounding box enclosing the polygon. The image is cropped to this box. To ensure spatial uniformity, a homography transformation (perspective warp) can be applied to flatten the skewed crop into a top-down rectangular view.
VGG16 requires a fixed input tensor dimension. Therefore, the cropped image is resized using bi-cubic interpolation to exactly 224x224 pixels across 3 RGB channels. Finally, pixel intensity normalization is applied. Raw pixel values ranging from 0 to 255 are divided by 255 to scale them to [0, 1]. Alternatively, standard ImageNet mean subtraction is applied to center the data around zero, which significantly accelerates the convergence of the gradient descent algorithm.

## 4.3 Data augmentation
To artificially expand the size of the training dataset and prevent the neural network from memorizing specific training examples (overfitting), a robust data augmentation pipeline was implemented using Keras's ImageDataGenerator.
Augmentations were applied dynamically on the CPU during the training loop, ensuring the GPU was constantly fed with entirely unique image variations. The augmentations included:
1. Horizontal Flipping: Vehicles can be parked nose-in or tail-in. Flipping the image horizontally perfectly simulates this variance.
2. Random Zoom (0.8x to 1.2x): Simulates different camera focal lengths and mounting heights.
3. Random Shearing: Mathematically distorts the image along the X or Y axis, simulating extreme perspective angles common in wide parking lots.
4. Brightness Shifts (0.5 to 1.5 multiplier): Forces the CNN to rely on structural edge features rather than absolute color intensity, ensuring the model remains accurate during dusk and dawn lighting transitions.

## 4.4 Model training
The training of the VGG16 occupancy model was executed on NVIDIA CUDA-enabled GPUs to leverage massive parallel tensor multiplication. The training architecture followed a two-phase transfer learning approach.
In Phase 1 (Feature Extraction), the VGG16 convolutional base was frozen. Only the weights of the newly appended dense classification head were allowed to update. This phase trained for 20 epochs, allowing the randomly initialized dense layers to learn how to interpret the complex feature maps generated by the pre-trained ImageNet base without propagating destructive, large gradients backward into the convolutional layers.
In Phase 2 (Fine-Tuning), the highest convolutional block of VGG16 (Block 5) was unfrozen. The learning rate was drastically reduced, and the model was trained for an additional 30 epochs. This microscopic adjustment allowed the high-level feature extractors (which normally detect complex objects like faces or animals) to specialize entirely in detecting vehicle chassis structures and asphalt textures.

## 4.5 Hyperparameters
Hyperparameter tuning is critical for achieving optimal convergence. The following hyperparameters were empirically selected after extensive grid-search testing:
- Input Shape: (224, 224, 3)
- Batch Size: 32 (Balancing GPU memory constraints with stable gradient updates)
- Base Learning Rate (Phase 1): 0.001
- Fine-Tuning Learning Rate (Phase 2): 0.0001
- Dropout Rate: 0.5 (Applied before the final classification neuron to force redundant feature learning and prevent overfitting)
- Epochs: 50 Total (20 Phase 1, 30 Phase 2)
- Momentum: 0.9 (Utilized with SGD to accelerate convergence across flat loss landscapes)

## 4.6 Loss function
The objective of the training loop is to minimize the error between the model's prediction and the ground truth. Since this is a binary classification problem (Vacant vs. Occupied), Binary Cross-Entropy (BCE) was utilized as the loss function.
BCE mathematically heavily penalizes confident but incorrect predictions. If the model predicts a probability of 0.99 (Occupied) but the ground truth is 0 (Vacant), the logarithmic nature of the BCE function causes the loss to spike exponentially. This forces the model to be highly calibrated in its probability assignments.

## 4.7 Optimizer
To update the weights of the network based on the computed loss, the Stochastic Gradient Descent (SGD) optimizer was selected over adaptive optimizers like Adam. While Adam often converges faster initially, SGD with Nesterov Momentum has been shown in deep learning literature to generalize better on complex image classification tasks, finding wider, flatter minimums in the loss landscape. The momentum parameter (0.9) ensures that the gradient updates build velocity in consistent directions, powering through minor local minimums caused by noisy batches.

## 4.8 Performance metrics
To rigorously quantify the model's capabilities, several statistical performance metrics were defined. The output of the test set evaluation generates a Confusion Matrix consisting of True Positives (TP), True Negatives (TN), False Positives (FP), and False Negatives (FN).
From these foundational numbers, the following metrics are derived:
- Accuracy = (TP + TN) / (TP + TN + FP + FN) : The overall percentage of correct predictions.
- Precision = TP / (TP + FP) : Out of all slots the model claimed were occupied, how many actually were?
- Recall = TP / (TP + FN) : Out of all the slots that were actually occupied, how many did the model successfully find?
- F1-Score = 2 * (Precision * Recall) / (Precision + Recall) : The harmonic mean, providing a balanced metric especially useful if the dataset has class imbalances.

## 4.9 Algorithm steps
The overall algorithmic execution for the edge inference node is defined sequentially:
1. Initialize VGG16 Occupancy Model, YOLOv8 Model, and Hybrid OCR engines into VRAM.
2. Establish continuous frame capture loop from RTSP stream.
3. On every Nth frame, execute YOLOv8 to detect vehicles at the entry gate.
4. If vehicle detected, crop plate bounding box and execute Hybrid OCR Logic (Run LPRNet, Run EasyOCR, Evaluate Regex Heuristic, Return Result).
5. Iterate through pre-defined slot polygon configuration.
6. For each polygon: calculate bounding box, crop frame, resize to 224x224, normalize pixels.
7. Batch process all slot crops through VGG16 tensors.
8. Apply 0.5 threshold to Sigmoid output to determine boolean state.
9. Compare new states against previous states in memory.
10. If state mutated, package JSON payload and transmit asynchronously to FastAPI cloud server.

## 4.10 Pseudocode
```
FUNCTION Hybrid_OCR_Engine(plate_image):
    confidence_easyocr, text_easyocr = Execute_EasyOCR(plate_image)
    text_lprnet = Execute_LPRNet(plate_image)
    
    regional_regex = "^[A-Z]{2}\d{1,2}[A-Z]{1,2}\d{3,4}$"
    
    IF Regex_Match(regional_regex, text_lprnet):
        RETURN text_lprnet  // Trust regional precision
    ELSE IF Length(text_lprnet) > 9 AND Length(text_easyocr) < 9:
        RETURN text_easyocr // Mitigate hallucination fallback
    ELSE:
        RETURN text_easyocr // Default fallback
```
